# M5Stamp-C3 ブロアファンコントローラ 部品表・配線表

対象ファン: **BitWindow BFB1012EH** (12V / 2.94A ≒ 35W / 7000rpm / 4PIN PWM)
マイコン: **M5Stack Stamp-C3 (SKU: C056-B)** — ESP32-C3 / 4MB Flash / USB-C (CH9102 経由) / 5V→3.3V DC-DC 内蔵
配線図: [wiring.png](wiring.png) ([wiring.svg](wiring.svg) が原本) / 実装図: [assembly_guide.png](assembly_guide.png)

## 0. SuperMini 版からの変更点

| 項目 | SuperMini 版 | Stamp-C3 版 |
|---|---|---|
| USB | native USB-CDC (GPIO18/19) | **CH9102 USB-UART ブリッジ** (UART0 = GPIO20/21) |
| Arduino 設定 | USB CDC On Boot: **Enabled** | USB CDC On Boot: **Disabled** (`Serial` は UART0 → CH9102) |
| 状態表示 LED | GPIO8 単色 LED | **GPIO2 SK6812 (RGB)** |
| ユーザーボタン | なし | **GPIO3** (外部ピン非露出) |
| 外部 IO | 0,1,3,4,5,6,7,10 他 | **G0,1,4,5,6,7,8,9,10,18,19,20,21** の 13 本 |
| 技適 | 無し (要 XIAO 等) | 取得済み |
| 実装 | 2×8 ピンソケット | 2.54mm ピッチ端子 (ピンヘッダを自分ではんだ付け) |
| PWM ピン | GPIO5 | **GPIO5 (変更なし)** |

## 3. MOSFET 選定の根拠

PWM 線のシンク電流は最大 5mA。2N7000 (Vgs(th) 最大 3V) を 3.3V で駆動するとオン抵抗は悪化するが、`5mA × 50Ω = 0.25V` で VIL(max) 0.8V に対し十分余裕がある。

## 4. 配線表

### Stamp-C3 側

| Stamp-C3 ピン | 接続先 | 備考 |
|---|---|---|
| **G5** (左列 3番) | FET ゲート (100kΩ で GND へプルダウン) | 25kHz PWM 出力 (LEDC) |
| GND (左列 1番) | FET ソース / 出力 GND / SATA の GND と共通 | **必須** |
| USB-C | ホストPCへ | 給電 + シリアル (CH9102)。入力は 5V のみ |
| 5V / 3V3 | 未接続 | 5V 端子と USB を同時に給電しない |

出力は **PWM と GND の 2 本のみ**。PWM ハブの「マザーへ挿す側の 4PIN オスプラグ」の **pin4 (PWM, 青)** と **pin1 (GND, 黒)** を使う。12V (pin2) と Tach (pin3) は触らない。

#### Stamp-C3 で使ってはいけないピン

| ピン | 理由 |
|---|---|
| **G20 / G21** | UART0 TX/RX。CH9102 に接続済みでシリアル通信に使用中 |
| **G8 / G9** | ストラッピングピン。G8 は書き込み時 High 必須 (プルダウン厳禁)、G9 は Low で書き込みモード |
| G2 | オンボード SK6812 (かつストラッピング)。外部非露出 |
| G3 | オンボードユーザーボタン。外部非露出 |
| G18 / G19 | native USB D-/D+。USB は CH9102 側なので GPIO として使えるが、起動直後に USB-JTAG 機能が有効なため PWM 用途には避ける |

→ 空いている **G0, G1, G4, G5, G6, G7, G10** から選ぶ。本設計では PWM=**G5**。

### ファン 4PIN コネクタ側

| Pin | 名称 | 線色 | 接続先 |
|---|---|---|---|
| 1 | GND | 黒 | SATA の GND (Stamp-C3 の GND と共通) |
| 2 | +12V | 赤 | SATA の +12V (黄) |
| 3 | Tach | 黄/緑 | **未接続** (PWM ハブがタコを返さないため) |
| 4 | PWM | 青 | FET ドレイン |

### FET (2N7000 / TO-92)

| 端子 | 接続先 |
|---|---|
| S (ソース) | GND |
| G (ゲート) | Stamp-C3 **G5** + 100kΩ → GND |
| D (ドレイン) | 出力 PWM → ハブ pin4 (青) |

## 4.5 プリント基板兼ケース (PETG / Bambu Lab A1 mini)

配線図: [assembly_guide.png](assembly_guide.png) (左: 下から見た裏面配線 / 右: 上から見た部品配置)

ベース板が基板を兼ねる。表面に部品、裏面の溝に 0.65mm スズメッキ線をはめて各穴ではんだ付けする。部品はすべて蓋の中に収まる。

| ファイル | 内容 | 印刷向き |
|---|---|---|
| `stampc3_base.stl` | 基板兼ベース (板厚 2mm + 下側スカート 4mm)。穴・裏面溝・刻印付き | 出力済みの向きのまま (板の上面がベッド側) |
| `stampc3_lid.stl` | 蓋。Stamp 上の窓、USB-C 開口、出力端子穴、ベースとのスナップ溝 | 出力済みの向きのまま (天面がベッド側) |
| `stampc3_bottom.stl` | 底蓋。Stamp 直下に LED 用の窓 | そのまま |

推奨設定: PETG / 0.4mm ノズル / 0.2mm レイヤー / 壁 3 周 / インフィル 25% / サポート不要。穴は 1.25mm (ヘッダ・出力) と 1.0mm (2N7000・抵抗)。きつい場合は 1.2mm ドリルで通す。

### 部品配置 (上から見た図)

- Stamp-C3: **付属ヘッダをピン下向き**ではんだ付けし、22 穴に挿す。USB-C は G0/G1 側の端で、蓋の開口に合わせる
- **状態 LED は下向き**。ベース板と底蓋の Stamp 直下を抜いてあり、下から見える
- 2N7000: Stamp 左列から 4 ピッチ左。**平らな面を外側 (Stamp と反対) に向け**、上から S / G / D
- 100kΩ: Stamp 左列から 2 ピッチ左に縦に寝かせる。リードの間隔は 10.16mm
- 出力 2P: 一番左。上が GND、下が PWM。ピンヘッダか、0.65mm 線を立てて端子にする

### 裏面配線 (0.65mm スズメッキ線を溝にはめる)

| 線 | 経路 | 
|---|---|
| GND | Stamp GND (左列1番) → 100kΩ 上端 → 2N7000 S → 出力 GND (一直線) |
| GATE | Stamp G5 (左列3番) → 下へ → 100kΩ 下端 → 上へ → 2N7000 G |
| PWM | 2N7000 D → 出力 PWM |

各経路と別ネットの穴とは最小 2.54mm 離してある。裏面には `G5 / GND / PWM / 2N7000 / USB` を下から見て読める向きで刻印してある。Stamp のその他 20 ピンは機械的固定のみで配線しない。ヘッダの突き出しは 1.5mm 程度に切る。

### 組み立て順

1. 2N7000 と 100kΩ を表から挿し、裏で足を溝に沿わせて仮止め
2. 0.65mm 線を 3 本切り、溝にはめて各穴ではんだ。余った足は切る
3. 出力 2P を挿してはんだ
4. ヘッダ付き Stamp-C3 を挿してはんだ (G5 と GND は線と一緒に、残りは固定用)
5. テスターで G5–GND 間が約 100kΩ、GND–PWM 間が開放であることを確認
6. ベースを下から蓋に押し込みスナップ。底蓋を押し込む

## 5. 組み立て前に確認すること

1. **ファンの PWM プルアップ電圧をテスターで測る** (5V なら本設計どおり)。
2. **GND が共通になっているか**。Stamp-C3 をホストの USB から給電すればホスト PSU 経由で SATA の GND と共通になる。別の AC アダプタから給電しない。
3. **FET 無しで直結しない**。5V プルアップのファンに ESP32-C3 (絶対最大定格 3.6V) を直結すると破損する。
4. **USB ドライバ**: Linux は標準ドライバで `/dev/ttyACM0` (環境により `/dev/ttyUSB0`) として見える。macOS/Windows は CH9102 ドライバを導入。

## 6. ファームウェアの要点

SuperMini 版から変更するのは以下だけ。

- PWM: **LEDC 25kHz / 10bit**、`duty_out = 1023 - duty_target` (変更なし)
- `PIN_PWM = 5` (変更なし)
- 状態 LED を SK6812 (G2) に変更 (実装済み): arduino-esp32 v3 は `rgbLedWrite(2, r, g, b)`、
  v2 系は `neopixelWrite`。ファーム側で `ESP_ARDUINO_VERSION_MAJOR` を見て自動で切り替える
  - **boot=青 / host 制御=緑 / failsafe=赤**
- フェイルセーフ・シリアルプロトコルは変更なし (ファーム `1.1.0`)

### 書き込み手順 (Arduino IDE)

1. ボードマネージャで **esp32 by Espressif Systems** を入れる
2. ボード: **ESP32C3 Dev Module** (または M5Stack ボードパッケージの **M5StampC3**)
3. **USB CDC On Boot: Disabled** (Enabled にすると `Serial` が native USB に向き、CH9102 側に何も出ない)
4. 書き込みは CH9102 の DTR/RTS による自動リセットで入る。失敗する場合は G9 を GND に落としたままリセット
5. `screen /dev/ttyACM0 115200` などで `P` を送り `PONG pwmfan 1.1.0` が返れば成功

### ホスト側 (pwmd.py) の注意

CH9102 の DTR/RTS は ESP32-C3 の EN / G9 に繋がっているため、ポートを開くと**リセットが掛かる**。

**実測 (2026-10-22 / Ubuntu 26.04 + cdc_acm)**: `dtr=False` / `rts=False` を open 前に
セットしても、`stty -hupcl` を併用しても**リセットは防げない**。cdc_acm が open 時に
一度 DTR を上げるため。open のたびに `rst:0x1 (POWERON)` が起き、ROM ブートログが
9 行 (236 bytes) 流れてくる:

```
ESP-ROM:esp32c3-api1-20210207
rst:0x1 (POWERON),boot:0xc (SPI_FAST_FLASH_BOOT)
... entry 0x403cbf10
```

リセット自体は**安全側**なので許容する (boot = 100% 全開 / LED 青)。ただし
**ブートログを応答と取り違えると `set_duty` が失敗 → 再オープン → 再リセットの
ループに陥る**ため、ホスト側で読み捨てが必須。[`pwmd.py`](../pwmd.py) の
`SerialBackend` は `_drain()` でブートログを捨て、`OK / ST / PONG / VER / ERR`
で始まる行だけを応答として受け付ける (回帰テスト `[6]`)。

シェルから叩くときは、ディスクリプタを開きっぱなしにすれば追加のリセットは起きない:

```bash
sudo bash -c '
exec 3<>/dev/ttyACM0
stty -F /dev/ttyACM0 115200 raw -echo
timeout 1.5 cat <&3 >/dev/null     # ブートログを捨てる
echo "P" >&3; read -t 2 -r l <&3; echo "$l"
'
```

pyserial で開く場合はこの形 (DTR/RTS を落とすこと自体は他のアダプタで効くので残す):

```python
ser = serial.Serial()
ser.port = "/dev/ttyACM0"
ser.baudrate = 115200
ser.dtr = False
ser.rts = False
ser.open()
```

## 7. 現行 (BMC Web API) 版との関係

SuperMini 版と同じ。マザーボードの SYSFAN ヘッダーは使わず BMC から独立。Stamp-C3 が故障したら PWM 線を SYS_FAN4 に差し替えるだけで BMC 版へ戻せる。

## 7.5 既知の問題: 極性が反転している (2026-10-22 実機)

**症状**: `D 20` でファンが高速、`D 100` でほぼ停止。つまり **ファン速度 = 100 - duty**。
FET によるオープンドレイン反転が効いておらず、G5 の信号がそのまま PWM 線に出ている。

**切り分け手順** (SYS_FAN4 を抜いて単独駆動にしてから行うこと。繋いだままだと
BMC のプッシュプル出力と競合して判定を誤る):

| 試験 | 設計どおりなら | 反転しているなら |
|---|---|---|
| `D 20` | 静か | **うるさい** |
| `D 100` | 全開 | **ほぼ停止** |
| failsafe (30秒無通信) | 全開 | **静かなまま温度上昇** |

`D 50` はどちらの極性でも 50% になるので、切り分け中の暫定保持に使える。

**応急処置**: `config.ini` に `[serial] invert = true`。ホスト側が `100-duty` を送る。

**この応急処置で直らないもの**:

- ファームの failsafe (無通信 30 秒 → duty 100) は**ファン 0% を意味したまま**。
  デーモンがハングしてから systemd が再起動するまでの数十秒、冷却が止まる
- Stamp-C3 の電源が落ちたときに「ゲート 100kΩ プルダウン → FET OFF → PWM 線が
  5V → 全開」という安全設計も失われる (ホスト停止時は SATA 12V も切れてファン
  ごと止まるため実害は小さいが、設計意図からは外れる)

**恒久対策** (どちらか):

1. **配線を直す** — 出力 PWM が FET のドレインではなくゲート側ノードに繋がって
   いないか確認する。テスターで「出力 PWM ↔ G5 が導通する」「出力 PWM ↔ GND が
   ≈100kΩ」なら確定。この場合 **G5 がファンの 5V プルアップに直接さらされて
   おり** (絶対最大定格 3.6V 超)、内部クランプで生き延びているだけなので要修正
2. **ファームの反転を外す** — `applyDuty()` の `PWM_MAX - raw` を `raw` にする。
   failsafe と boot は正しく全開に戻るが、電源断時の安全性は 1 でしか戻らない

※ 2N7000 の S/D 逆挿しも疑ったが、それだとボディダイオードで常時 0% に張り付き
**変調しなくなる**はずなので症状と合わない。

### シリアルプロトコル

| 送信 | 応答 | 意味 |
|---|---|---|
| `D <0-100>` | `OK D=<n>` | duty 設定 (このコマンドがフェイルセーフのタイマもリセットする) |
| `S` | `ST duty=<n> src=<host\|failsafe\|boot> age=<ms>` | 状態取得 |
| `P` | `PONG pwmfan <ver>` | 疎通確認 |
| `V` | `VER pwmfan <ver> pin=<n> freq=<hz>` | ビルド情報 |
| - | `EV failsafe timeout -> 100%` | 非同期通知 (ホスト沈黙時)。boot 中は出さない |

### 状態 LED (G2 / SK6812)

| 色 | 状態 | duty |
|---|---|---|
| 青 | boot — ホストとまだ一度も喋っていない | 100% |
| 緑 | host — ホストの指示どおり制御中 | 指示値 |
| 赤 | failsafe — ホストが 30 秒沈黙した | 100% |

### 検証結果 (モックファーム / 2026-10-22)

```

[3] Controller  ヒステリシス内は据え置き + heartbeat は送出

[5] 障害復旧    ポート切断後に自動再オープンして送信成功

```
